# 인스타오토 · 첨부 원본에 적용한 수정본

## 기존 Manus 프로젝트에 적용

1. 기존 프로젝트와 개발 DB를 백업하고 첨부 ZIP의 instaauto 폴더 **내용**을 프로젝트 루트에 반영합니다. 기존 관리자, .env.local, 토큰 암호화 키, DB를 유지합니다.
2. 기존 개발 DB 연결을 확인하고 Node.js 22 이상에서 npm ci와 npm run migrate를 실행합니다. 마이그레이션 이력을 기준으로 001~004 중 누락분만 반영합니다. 테스트에는 별도의 빈 instaauto_test DB를 사용합니다.
3. MEDIA_SPOOL_DIR은 서버와 워커가 함께 읽고 쓰는 영속 디스크의 절대 경로로 지정합니다. 이 경로는 웹 정적 경로 밖에 두고 용량을 점검합니다. 컨테이너를 교체해도 같은 파일이 보여야 합니다. 워커 DB 풀은 기본 8, 최소 2입니다.
4. 기존 관리자로 npm run dev와 별도 npm run worker를 실행해 개발 Preview에서 확인합니다. 상시 운영에는 API, 워커, DB, 디스크가 PC와 별도로 지속 실행되어야 합니다. 예약 게시 및 OAuth 실승인은 여기서 검증되지 않았습니다.

## 제작 파일 사용 순서

- 운영 계정을 등록하면 워커가 폴더 준비 작업을 등록합니다. 기존 계정도 마이그레이션 시 포함됩니다. 계정 등록에는 비즈니스 유형을 요구하지 않습니다.
- ‘콘텐츠·예약’에서 계정과 형식을 선택하고 제목을 입력합니다. 기존 콘텐츠에서 파일을 첨부하거나 설정한 공급자의 이미지 생성 기능을 사용할 수 있습니다. 첨부 또는 생성에 성공한 파일은 서버에 먼저 보관되고 Drive 보관 작업이 자동 등록됩니다.
- Drive에 연결하면 ‘인스타오토 / @계정 / 피드’와 ‘인스타오토 / @계정 / 릴스’에 저장합니다. 폴더 연결에는 계정 내부 ID를 사용합니다. 계정명이 바뀌어도 기존 폴더를 재사용합니다. 예시 파일명은 ‘2026-11-24_00-05-06_서울 야경.mp4’입니다. 한국시간 기준이고, 동시에 동명 파일이 생기면 _01, _02를 붙입니다.
- 릴스 콘텐츠에는 이미지 또는 원본 영상과 음원을 첨부한 뒤 길이를 선택해 MP4 합성을 예약할 수 있습니다. SRT 또는 WebVTT 자막은 선택 사항입니다. FFmpeg와 한글 글꼴이 설치된 워커가 720×1280 H.264/AAC 파일을 만들어 같은 보관 경로에 넣습니다.
- 보관 상태는 대기, 재시도, 검증 완료로 구분합니다. 원격 파일의 ID, 상위 폴더, 바이트 수 및 SHA-256을 대조한 뒤에만 Drive 파일 링크를 표시합니다. 네트워크 응답이 유실돼도 DB에 기록한 동일한 원격 ID를 재확인합니다. 로컬 임시 원본은 현재 보존하며, 기간별 정리 기능은 후속 구현 대상입니다.

## 사업자 연결 시 필요한 설정

Google Drive는 운영자가 승인한 5TB 계정이 대상입니다. 실제 계정 용량 측정과 실업로드는 남아 있습니다. Google Cloud에 Drive API를 활성화하고 웹 OAuth 클라이언트를 준비합니다. 서버 비밀 설정에 GOOGLE_DRIVE_CLIENT_ID, GOOGLE_DRIVE_CLIENT_SECRET, GOOGLE_DRIVE_REDIRECT_URI 및 기존 TOKEN_ENCRYPTION_KEY를 지정합니다. 등록할 콜백 주소는 개인 관리자 사이트의 HTTPS 주소 뒤에 /api/archive/callback을 붙입니다. 서버와 워커가 같은 키를 사용해야 합니다.

관리자가 설정·연동에서 Drive 연결을 승인하면 drive.file 권한과 갱신 토큰으로 워커가 작동합니다. 기본은 앱이 전용 루트 폴더를 생성하는 방식입니다. GOOGLE_DRIVE_ROOT_ID를 사용하는 경우 이 앱이 접근할 수 있는 기존 폴더여야 합니다. 개인 Drive 파일은 비공개 보관용입니다. Meta 게시용 미디어 전달 URL 구성은 별도 작업입니다.

이미지 실호출 전 서버에는 OPENAI_API_KEY, 사용자가 선택한 OPENAI_IMAGE_MODEL, 1회 예상비용 상한 OPENAI_IMAGE_MAX_COST와 동일 화폐 단위의 해당 월 monthly_budgets 모델 행이 필요합니다. 설정 또는 예산이 없으면 생성을 보류합니다. 실제 과금액을 확인하기 전에는 예상 상한을 예약 상태로 보관합니다. provider_settings에서 단계별 공급자·모델을 선택하며, 새 공급자의 코드 연결부는 src/providers에 추가합니다. 기본 제공 연결부는 OpenAI 텍스트·이미지이며 타사 생성과 AI 영상·음악 생성은 미구현입니다.

## 검증 결과와 재현

- 격리 PostgreSQL에서 001~004를 적용하고 npm test의 10개 검사를 통과했습니다. CSV 200행 중복 방지, 게시 응답 유실·긴급 정지·성과 미수집, 계정별 폴더, 시간대와 이름 충돌, 응답 유실 후 같은 파일 ID 재사용, 이미지 호출 중복 방지, 영상·음성 디코딩과 자막 픽셀 확인을 포함합니다.
- 개발 API와 실제 Chromium에서 관리자 로그인, 6개 메뉴, 계정 생성·새로고침·수정·재로그인, 실제 XLSX 200행을 두 번 적용한 후 중복 0건, 한 PNG를 이름을 바꿔 두 번 보관한 후 대기 1건을 확인했습니다. 브라우저를 닫고 독립 워커를 종료·재시작한 후 예약 1건이 정확히 한 번 처리돼 미연동 보류에 도달했습니다.
- 같은 브라우저 검증은 빈 전용 instaauto_test DB를 마이그레이션한 상태에서 프로젝트 루트의 python3 scripts/verify-browser.py로 실행합니다. Python Playwright, openpyxl 및 Chromium이 필요합니다. CHROMIUM_EXECUTABLE로 브라우저 경로를 지정할 수 있습니다.
- Google과 OpenAI 원격 응답은 검증 중 테스트 전송 계층으로 대체했습니다. 실계정 로그인·실업로드, 유료 생성, Meta 게시 및 지역 판정, 100~200계정 동시 운영 부하는 검증 범위 밖입니다. 분석·자동 생성·성과 수집·후속 게시 전체 자동화와 R2 미디어 전달은 후속 작업입니다. 재확인은 기존 Manus Preview에서 별도로 진행합니다.
